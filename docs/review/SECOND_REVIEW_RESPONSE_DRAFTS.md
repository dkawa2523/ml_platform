## SR01: Extract ClearML Parameter Mapping

Reply draft:

We agree that ClearML parameter mapping was still too concentrated. This has
been split so `clearml/params.py` owns ClearML parameter transport, value
normalization, legacy key aliases, connected parameter coercion, and nested
config application. `clearml/adapter.py` now delegates those details and remains
focused on ClearML SDK operations. Tabular model-suite policy, quality presets,
and ensemble decisions remain in the tabular package. Verification: targeted
ClearML mapping tests, full pytest, compileall, and ruff check passed under
`uv run python`.

## SR02: Split Evaluation Artifact Writers

Reply draft:

We agree that `evaluate_model_candidates` had too many artifact-writing
responsibilities. It now keeps ranking and `EvaluationResult` assembly, while
leaderboard outputs, prediction tables/plots, best-model copy/JSON, and
decision/report outputs live in focused writer modules. Existing artifact
names, table names, plot names, and public API compatibility are preserved and
covered by writer tests plus characterization tests. Verification: writer tests,
tabular characterization tests, full pytest, compileall, and ruff check passed
under `uv run python`.

## SR03: Separate ClearML Reporting From Tabular Plotting

Reply draft:

We agree that ClearML reporting should not rebuild tabular plots from CSV data
when the tabular package can produce the plot artifacts directly. ClearML
reporting no longer reconstructs prediction or leaderboard plots from CSV
tables. It now uploads artifacts/tables, publishes scalar metrics, and reports
existing plot artifacts generated by the tabular package; ClearML-specific
report/upload API calls remain in `clearml/reports.py`.
Verification: ClearML mapping tests, full pytest, compileall, and ruff check
passed under `uv run python`; grep confirms the removed plot reconstruction
helpers are not present in `clearml/reports.py`.

## SR04: Delete ClearML Bootstrap After Remote Agent Verification

Reply draft:

We agree the direct-entrypoint bootstrap is technical debt. It is intentionally
deferred because current ClearML templates still preserve direct
`clearml/app.py` and `clearml/pipelines.py` compatibility. We will remove the
bootstrap only after Remote Agent template execution is verified without it.
Gate: actual remote training and inference template runs must pass without
direct-entrypoint path injection.

## SR05: Move Legacy Dict Compatibility Out Of RunConfig

models stay focused on field definitions, parsing, and validation.
Verification: config model tests, full pytest, compileall, and ruff check passed
